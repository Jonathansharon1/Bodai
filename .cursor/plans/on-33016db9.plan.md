# PostHog Analytics Integration Plan

## Overview

Integrate PostHog as the primary analytics platform to collect user behavior data, track key events, and enable data-driven product decisions. PostHog provides product analytics, session replay, feature flags, and A/B testing in one platform.

## Implementation Steps

### 1. PostHog Setup & Configuration

**Files to create/modify:**

- `client/src/lib/posthog.js` - PostHog initialization and configuration
- `client/src/index.js` - Wrap app with PostHog provider
- `.env` (client) - Add PostHog API key

**Actions:**

- Install `posthog-js` package in client
- Create PostHog initialization utility with proper config
- Set up environment variable for PostHog project API key
- Configure PostHog with privacy settings (GDPR compliance)
- Enable automatic pageview tracking
- Configure session recording (optional, can be enabled later)

### 2. User Identification with Clerk

**Files to modify:**

- `client/src/index.js` - Identify users after Clerk authentication
- `client/src/AppRouter.jsx` - Sync user properties on login

**Actions:**

- Identify PostHog users with Clerk user ID
- Set user properties from Clerk profile (email, name, subscription type)
- Update user properties when subscription changes
- Handle user identification on sign-in and sign-up

### 3. Core Event Tracking

**Files to modify:**

- `client/src/pages/SignInPage.jsx` - Track sign-in events
- `client/src/pages/SignUpPage.jsx` - Track sign-up events
- `client/src/pages/OnboardingPage.jsx` - Track onboarding completion
- `client/src/AppRouter.jsx` - Track video analysis events
- `client/src/pages/PricingPage.jsx` - Track pricing page views and clicks
- `client/src/pages/SubscriptionPage.jsx` - Track subscription events

**Key Events to Track:**

- `user_signed_up` - New user registration
- `user_signed_in` - User login
- `onboarding_completed` - Onboarding flow completion (with goal selected)
- `video_uploaded` - Video file selected/recorded
- `video_analysis_started` - Analysis request initiated
- `video_analysis_completed` - Analysis successfully completed
- `video_analysis_failed` - Analysis error occurred
- `analysis_viewed` - User viewed analysis results
- `practice_mission_started` - User started a practice mission
- `practice_mission_completed` - User completed a practice mission
- `journey_created` - User created a new journey
- `pricing_page_viewed` - User viewed pricing page
- `subscription_upgrade_clicked` - User clicked upgrade button
- `subscription_upgraded` - User successfully upgraded
- `page_viewed` - Automatic pageview tracking (already enabled)

**Event Properties:**

- Include relevant context (goal type, subscription tier, journey ID, analysis ID, etc.)
- Track error messages for failed events
- Include user properties (subscription type, onboarding status)

### 4. User Properties & Segmentation

**Files to modify:**

- `client/src/AppRouter.jsx` - Set user properties on profile load
- `client/src/components/Dashboard.jsx` - Update properties when data changes

**User Properties to Track:**

- `subscription_type` - free, premium, pro
- `onboarding_goal` - Primary goal selected
- `analyses_count` - Total analyses completed
- `journeys_count` - Number of journeys created
- `first_analysis_date` - Date of first analysis
- `last_analysis_date` - Date of most recent analysis
- `has_completed_onboarding` - Boolean
- `account_created_at` - Sign-up date

### 5. Error Tracking

**Files to modify:**

- `client/src/AppRouter.jsx` - Track API errors
- Global error boundary (if exists) - Track React errors

**Actions:**

- Track failed API requests with error details
- Track client-side errors
- Include error context (endpoint, user action, error message)

### 6. Feature Flags (Optional - Future)

**Files to create:**

- `client/src/hooks/useFeatureFlag.js` - Custom hook for feature flags

**Actions:**

- Set up PostHog feature flags for gradual rollouts
- Create hook to check feature flags in components
- Enable A/B testing capabilities

### 7. Session Replay (Optional - Future)

**Actions:**

- Enable session replay in PostHog config
- Configure privacy settings (mask sensitive data)
- Set sampling rate for performance

### 8. Backend Event Tracking (Optional)

**Files to modify:**

- `server.js` - Add PostHog Node.js SDK for backend events

**Actions:**

- Install `posthog-node` in backend
- Track server-side events (analysis processing time, API errors)
- Track subscription webhook events
- Only if needed for server-side analytics

## Environment Variables

Add to `client/.env`:

```
REACT_APP_POSTHOG_KEY=your_posthog_project_api_key
REACT_APP_POSTHOG_HOST=https://app.posthog.com (or self-hosted URL)
```

## Privacy & Compliance

- Configure PostHog to respect user privacy preferences
- Mask sensitive data in session replays (if enabled)
- Comply with GDPR (PostHog supports this)
- Allow users to opt-out if required by law

## Post-Implementation

1. Create PostHog dashboards for key metrics:

   - User acquisition funnel
   - Activation rate (first analysis completion)
   - Feature adoption (journeys, practice missions)
   - Conversion funnel (pricing → subscription)
   - Retention metrics

2. Set up alerts for critical events (e.g., analysis failures)

3. Create cohorts for user segmentation (e.g., "Users who completed first analysis", "Premium subscribers")

4. Analyze data to identify:

   - Drop-off points in onboarding
   - Most/least used features
   - Conversion blockers
   - User engagement patterns
